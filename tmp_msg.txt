feat(聊天): 附件回收、Web 导出下载与若干观感/正确性修复，补齐 UI 截图

一、孤儿附件回收
- services/attachment_gc.dart：判据只有一个 —— 当前所有消息引用的 ref 集合；
  不在集合里的才删，顺手清掉崩溃残留的 .part。判定逻辑拆成纯函数 orphansOf 便于测试。
- 存储空间页新增「可回收空间」区（只在真有孤儿时出现）+ 二次确认 + 清理后自动重扫。
  未传 controller 时不给入口：没有引用集合就没有判据，宁可不做也不猜着删。

二、Web 端带附件导出
- services/web_download{,_stub,_web}.dart：条件导出，Web 用 Blob + <a download> 直接下载，
  其它平台 no-op（本来就走临时文件 + 分享）。导出处理器不再只提示「请换平台」。

三、修掉的其它问题
- 上传抽屉：矮屏/横屏/键盘顶起时会溢出 140px → 改为可滚动。
- 存储空间占用条：色段只有宽度、高度是 0（ColoredBox 无子节点，Row 按内容量高），
  整条永远只剩背景色 → crossAxisAlignment.stretch，并加 Key 用断言锁住段数与配色。
- 占用条占比极小时改为「构成模式」：整条画本应用自己的分布，占磁盘多少交给文字说明，
  免得用户把一条 3px 发丝当成「没有数据」。
- 上下文预算：附件文本与图片（按 1000 token/张粗估）计入 token 统计，避免「看着很空却 400」。
- 上下文裁剪：一条消息自己就超预算时，过去会把整轮裁成空（用户刚说的话也丢了）→
  现在保证最新一条永远保留。
- 文本附件被截断时在 prompt 里写明「全文 N 字，只给前 M 字」，不再让模型以为读完了。
- 模型不支持视觉时的抽屉提示文案缩短，避免在词中间断行。
