feat(聊天): 支持发送文件/图片，新增存储空间页与模型能力快照

一、模型能力快照（回答「怎么判断模型能不能传图」）
- tools/update_model_capabilities.mjs：一条命令拉 models.dev 的 api.json → 裁剪成
  紧凑数组 → gzip 成 assets/data/model_capabilities.json.gz（1589KB → 70KB）。
  带 --check（只报告是否有更新）与 --offline（用 .cache 里的原始响应重建）。
- lib/services/model_capabilities.dart：懒加载 + 三级匹配（精确 → 去 provider 前缀 →
  归一化去日期/latest）+ 名字启发式兜底；缺资产不崩。
- lib/services/model_vision.dart：视觉能力三层优先级（用户指定 > 快照 > 启发式）。

二、聊天附件
- 存储：lib/services/attachment_storage{,_io,_stub}.dart，内容寻址（sha256），
  同一份文件只落一份；原子写（先 .part 再 rename，并发安全）；读不到一律 null 不抛。
- 接入：attachment_intake（体积限制 / 图片压缩到长边 1568 / 文本抽取 / 存盘），
  单文件 20MB、图片 5MB、文本 20 万字符，全部常量只有一份真值。
- 模型：ConversationMessage.attachments + MessageAttachment（只存元数据，字节在库里）。
- UI：输入栏回形针按钮 + 底部抽屉（文件 / 相册 / 照相；后两者仅在模型支持视觉时出现，
  照相在 PC 隐藏）+ 输入区上方附件胶囊（可逐个移除）+ 气泡内附件列表（图片可点开看大图）。
- 回溯：把被丢弃消息的附件一起倒回输入区（只发文件不写字也能回填）。
- 设置：外观 → 界面元素新增「显示上传文件按钮」；模型编辑页新增视觉三态
  （自动判断 / 支持图片 / 不支持图片）。

三、请求链路多模态
- LlmRequest.messages 从 Map<String,String> 放宽到 Map<String,dynamic>；
  文本附件拼进 content，图片走 image_url 部分数组；Anthropic 侧转换成 image/base64 块。
- 每次请求最多带 4 张图（base64 体积控制），图片按引用缓存，读失败静默跳过。

四、导出与备份（不重复存）
- 单会话导出：有附件时打包 zip（conversations.json + attachments/<ref>，按引用去重）。
- 全量备份：流式写入 attachments/，导入时按内容哈希幂等还原（已存在的直接跳过）。

五、存储空间专题页
- services/storage_usage_service.dart + pages/settings/storage_settings_page.dart：
  七类口径（会话/角色卡/世界/缓存/下载/附件/其他），总览占用条 + 分类占比 + 下钻明细。
- 拿不到磁盘容量写「未知」，读库失败明确提示原因与重试，不静默给偏小的数。
- 设置 → 数据与安全 → 存储空间。
